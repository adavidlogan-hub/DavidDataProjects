# Targeted pass 3 brief (largest UNKNOWN counties, second round)

Applies on top of phase1/CHECKLIST_BRIEF.md and phase1/TARGETED_BRIEF.md; all their rules still apply (public online sources only, never contact a county, never guess, never get around bot protection or robots.txt, rules 43 and 47, fixed tag rule, no em dashes, en dashes, or emojis). Every network request goes through the fetch module (`python3 -m txprecinct.get`); never use curl or another fetch tool. The fetch client now keeps cookies in memory within one process, so session-cookie redirects (Laserfiche portals) work.

Read each county's current phase1/evidence/<County>.json first: earlier passes list what was already tried. Do not repeat a dead end; go deeper or try a new angle. Budget about 15 fetches and 4 web searches per county.

## Angles for this round, in order of value
1. **Vendor live-results sites with stored state.** Several counties use livevoterturnout.com ENR sites (Williamson, Ellis, Hays) or other vendor sites. Open the page source, find the data files it loads (JSON, XML, CSV, per-precinct files), fetch them, and look for update timestamps or per-update history, the way Clarity keeps versioned updates. A page that shows "Website Updated: <time>" together with per-precinct candidate votes that include election-day votes is a printed time; it settles END or LIVE only if that time falls on election night and no upload time contradicts it (rule 47). Today's copy normally shows the final canvass state; say so if that is all you see.
2. **Every report file, with upload times.** On each county's results and archive pages (and their subfolders, document center folders, and agenda or canvass attachments), list every file for the three elections, including unofficial, cumulative, election night, and precinct reports, with printed run time and the server's Last-Modified (see CHECKLIST_BRIEF check 2 for how to view it). Note when a server stamps every file with the request time (CivicPlus DocumentCenter often does): then there is no upload time, and the printed run time decides under rule 47.
3. **Check 4, third-party election-night pages** (TARGETED_BRIEF item 2): local newspaper or TV pages that publish per-precinct candidate votes credited to the county's election-night results, with an election-night published or updated time. Web search is allowed to locate such pages; the fetched page is the evidence, never the search snippet.
4. **County statements** (TARGETED_BRIEF item 4) are leads only.

A separate archived-file sweep (phase1/archive_file_sweep.py, results at phase1/targeted/sweep/<County>/index.json on the wayback-data branch) is running on GitHub Actions. If `git show origin/wayback-data:phase1/targeted/sweep/<County>/index.json` exists when you reach a county, read it: each replay lists the archived file, the original server's Last-Modified converted to local time (orig_last_modified_local), PDF printed times, a text sample, and flags upload_on_election_night and printed_on_election_night. A flagged file decides an election only if its content shows per-precinct candidate votes including election-day votes (END or LIVE), or county totals with the rule 43 conditions (LATER). Some PDF headers are in a shifted font encoding (glyph code = character minus 0x1C); numbers are plain. If the sweep has not landed, say "sweep pending" in your note.
